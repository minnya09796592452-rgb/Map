IMPORTANT CORRECTION TO THE SIMPLE PROFILE DECODER:
The V26.2 sample CSV shows raw ushort / 65535. That is useful as a
raw numeric preview, but it does not by itself reproduce Map.Load.
The actual loader first calls ToCompressStable() before Decompress().

Source: extracted/V24/CS_SOURCE/Assembly-CSharp__Funlabs__MPExtensions.cs

Compress(float value):
  if value > 1: value = 1
  if value < 0: value = 0
  return (ushort)(value * 65535f)

Decompress(ushort value):
  return (float)value / 65535f

IsCompressStable(ushort value):
  return value == value.Decompress().Compress()

GetCompressStable(ushort value):
  if already stable, return value
  for distance = 1, 2, 3, ...
    test lower candidate first (value - distance), if in range
    if lower candidate is stable, return lower
    otherwise test upper candidate (value + distance), if in range
    if upper candidate is stable, return upper

InitializeCompressStableValues():
  precomputes the mapping for all 65,536 ushort inputs.

ToCompressStable():
  returns the precomputed _toCompressStable[value].

Therefore exact runtime-compatible decoding is:
  raw = little_endian_uint16(bytes[2*k : 2*k+2])
  stable = ToCompressStable(raw)
  height = float32(stable) / float32(65535)

The order is row-major as implemented by nested i then j loops.
Do not apply a row flip unless a separate source/runtime test proves it.
The V26.2 raw sample CSV has not applied this stable-value lookup.
Recompute runtime-final heights through the stable table before claiming
bit-for-bit Unity Map.Load equivalence.

Earlier V19 byte-profile heuristics treated 514x257 8-bit as a candidate.
That was a raw-byte guess, not a format conclusion. Later source code and
V26.2's UInt16 profile supersede that heuristic.
